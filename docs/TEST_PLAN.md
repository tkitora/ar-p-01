# テスト計画 p-01

結果は `docs/FINDINGS.md` に記録する。各テストは「実施日・環境・結果・ログの場所」を残す。

## 共通の前提

- 公式アプリは終了、スマホの BLE は OFF(または GUIDE01 のペアリング解除)
- GUIDE01 は充電済み
- ESP32 と PC は同じ Wi-Fi(2.4GHz)に接続
- ファームの環境は SDK サンプルと同じ(PlatformIO、`m5stick-c` 環境が基準)

---

## T0: 環境確認

- [ ] PlatformIO が動く(`pio --version`)
- [ ] SDK が `sdk/` に配置され、`libguide01_protocol.a` が対象ボード用に存在する
- [ ] Mosquitto が PC で動く(`server/` の設定を使用)
- [ ] 使用ボードとファームのバージョンを記録

## T1: スキャンと接続(Q1)

- [ ] `scan_connect_battery` をビルド・書き込み
- [ ] GUIDE01 を発見できる
- [ ] 接続できる
- [ ] バッテリー値が取得できる
- 合格: 接続とバッテリー取得ができる。失敗時はエラー内容を記録

## T2: API 棚卸し

- [ ] `full_demo` のソースと `guide01_protocol` ヘッダを読む
- [ ] 次の機能の有無を表にする(あり/なし/不明、該当する関数名)
  - テキスト表示 / 複数行 / スクロール / 画像・GIF / タッチ・ジェスチャ通知 / 表示クリア / 明るさ / 電源
- [ ] 送信できるデータ量の上限、推奨送信間隔(記載があれば)

## T3: テキスト表示(Q2)

- [ ] ESP32 から短い文字列を表示
- [ ] 日本語が表示できるか確認(できなければ制約を記録)
- [ ] 1行あたりに表示できる文字数、行数を実測
- [ ] 更新を繰り返しても表示が崩れないか(10回、100回)
- 合格: 短いテキストが表示できる。日本語の可否は別途記録

## T4: タッチ受信(Q3)

- [ ] タップ、スライド(前後・上下があればその向き)を、シリアルログに出す
- [ ] 検出できるジェスチャの種類を一覧にする
- [ ] 誤検出・取りこぼしの頻度の体感を記録
- 合格: タップとスライドの区別が付けて受信できる
- 不合格でも継続可能(ESP 側のボタンで代替)。ただし理由を記録

## T5: ログ表示とスクロール(Q4)

- [ ] 複数行のログ(10〜20件)を保持し、画面に収まる分を表示
- [ ] タッチ(または ESP ボタン)で上下スクロール
- [ ] 新着メッセージ到着時の動作(自動で最新へ/位置保持)
- [ ] 表示更新にかかる時間を計測(送信から表示まで、5回以上)
- 合格: スクロール操作でログを読める

## T6: BLE + Wi-Fi + MQTT 同時動作(Q5)

- [ ] GUIDE01 に BLE 接続した状態で Wi-Fi に接続
- [ ] ローカル Mosquitto に接続し、publish / subscribe
- [ ] 30分間の連続稼働で、切断・再起動・メモリ不足が起きないか
- [ ] 切断を意図的に起こし(Wi-Fi OFF/ON、GUIDE01 を遠ざける)、自動再接続するか
- [ ] 空きヒープの推移をログに残す
- 合格: 30分間、BLE と MQTT が両方維持される

## T7: エンドツーエンド(Q6)

- [ ] PC から MQTT でメッセージを送る → ESP32 が受信 → GUIDE01 に表示
- [ ] GUIDE01 のタッチ → ESP32 → MQTT で PC に通知
- [ ] 往復の遅延を測る(5回以上、平均と最大)
- 合格: 双方向の通信が成立する

## T8(任意): 発展確認

- [ ] 画像/GIF 表示の可否と速度(SDK が対応している場合のみ)
- [ ] 連続稼働時間(バッテリー消費)
- [ ] ESP32-S3 など別ボードでの再現(メモリ余裕の確認)

## 総合判定(FINDINGS.md に記載)

| 判定 | 条件 | 次のアクション |
|---|---|---|
